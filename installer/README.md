# installer/ — доставка системы

Здесь живёт **код продукта**: CLI `fraim`, генератор скиллов и адаптеры под харнесы.
Сами процедуры лежат в `../procedures/` и остаются движко-независимыми — этот каталог
только упаковывает их под целевой агент.

## Разделение ответственности

| Каталог | Что это | Меняется |
|---|---|---|
| `procedures/` | канонический источник: 13 процедур, движко-независимый markdown | когда меняется методология |
| `installer/` | CLI, генератор, адаптеры под харнесы | когда меняется способ доставки |

## Два разных инсталла

У системы, как у любого продукта, есть код и рабочее состояние — их ставят разные
механизмы, и путать их нельзя:

1. **Установка системы** — один раз на машину. Агент узнаёт про `/make-task`,
   `/run-task` и остальные. Это `fraim init`.
2. **Разворот в проекте** — один раз на проект. Появляются `ARCHITECTURE.md`,
   `CONVENTIONS.md`, `DECISIONS.md`, `ai/`. Это `/bootstrap` и `/onboard`.

## Установка

```sh
curl -fsSL https://raw.githubusercontent.com/modehustle/aiframework/main/installer/install.sh | sh
fraim init
```

`install.sh` клонирует репозиторий в `~/.fraim/src` и линкует бинарник в `~/.local/bin`.
Зависимости: `git` и POSIX-совместимый shell. Больше ничего — ни Node, ни Python
(Python используется только как необязательное удобство, чтобы безопасно дописать
разрешение в `~/.claude/settings.json`).

`fraim init` **идемпотентен**. Та же команда — это установка, обновление и подключение
только что появившегося харнеса. Отдельного `update` учить не нужно (он оставлен как
явный синоним).

## Команды

| Команда | Что делает |
|---|---|
| `fraim init` | собрать скиллы, разложить по найденным харнесам, дописать контекстный блок, завести реестр |
| `fraim status [ПУТЬ]` | вердикт сторожа по проекту; `--json` для машины |
| `fraim projects [add\|rm ПУТЬ]` | реестр проектов |
| `fraim doctor` | что и куда установлено, какая версия, что разошлось |
| `fraim show ИМЯ` | напечатать текст процедуры (для сред без скиллов) |
| `fraim build` | пересобрать артефакты репозитория: полезную нагрузку плагина и манифест |
| `fraim config` | что действует и откуда; `config set КЛЮЧ ЗНАЧЕНИЕ` |
| `fraim scaffold [ПУТЬ]` | развернуть скелет фундамента и `ai/` |
| `fraim publish [--check]` | копия проекта вне этой машины: проверить, создать, отправить, сверить |

### Детерминированные глаголы

Их зовут процедуры вместо ручной работы. Подробно — [DETERMINISM.md](DETERMINISM.md).

| Глагол | Заменяет |
|---|---|
| `fraim brief` | чтение фундамента по файлам с обрезкой на 200 строках: весь фундамент, доска и список глаголов одним выводом с меткой полноты |
| `fraim find КЛЮЧ…` | grep, который отдаёт строку без заголовка: запись целиком, ключи через ИЛИ, без учёта регистра |
| `fraim arch "РАЗДЕЛ" [--new] [--in ФАЙЛ]` | правку карты руками: заменяет ровно один раздел, остальные заголовки неприкосновенны |
| `fraim backlog` · `backlog-new СЛАГ` · `backlog-drop СЛАГ "ПОЧЕМУ"` | открытые вопросы, которые иначе остаются в чате |
| `fraim tasks [--json]` | обход `ai/tasks/` руками: доска, проекты и их прогресс |
| `fraim task-new СЛАГ [--master \| --parent М]` | карточку задачи руками: тело приходит потоком, шапку, место и коммит пишет глагол |
| `fraim task-master СЛАГ` | правку `kind` руками — задача становится проектом (по слову человека) |
| `fraim task-seal СЛАГ "ИТОГ" [--dropped]` | перенос карточки в архив руками; проект с открытыми подзадачами — **отказ** |
| `fraim investigate-new СЛАГ` | создание папки расследования и штамп provenance |
| `fraim investigate-seal СЛАГ` | архивацию расследования — **может отказать** |
| `fraim prune-mark` | маркер прунинга |
| `fraim stack-passport` | создание `STACK.md` по схеме |
| `fraim commit ВИД ТЕКСТ ПУТЬ…` | `git add` + `git commit` руками |
| `fraim undo [ХЕШ]` | `git reset` / `git revert` руками |
| `fraim restore ПУТЬ…` | `git restore` и удаление черновиков руками |

Некоторые отказывают: `task-new` — карточке без заголовка, «What and why» и «Done when»,
`task-seal` — проекту с открытыми подзадачами, `investigate-seal` — расследованию без исхода и уборки.
`fraim commit` и `fraim restore` не умеют «всё»: они трогают ровно перечисленные пути, и это
то, что не даёт `.env`, данным и чужой незаконченной работе ни уехать в историю, ни пропасть
при уборке.

### Копия вне машины — `fraim publish`

Развилка «какой хост, приватный или публичный» — настоящая, и она осталась **вопросом**:
команда спрашивает, а не догадывается, и публичным репозиторий становится только явным
выбором. Всё вокруг развилки — механика, и она повторяется на каждой отправке, поэтому
живёт в коде: проверить, чем можно опубликовать (и показать строчку установки под систему,
если нечем), создать репозиторий, прописать адрес, отправить и **сверить, что на хосте
лежит то же самое**.

Провайдер (`gh`, `glab`) — ускоритель, а не требование: пол всегда `--url ССЫЛКА`, то есть
любой хост, включая свой. Ни один отказ провайдера не заканчивается словом «нельзя».

Перед отправкой идёт проверка того, что уедет: **имена** — по всей истории (файл, стёртый
из дерева, лежит в паке и уезжает с первым push), **содержимое** — в текущем снимке. Тяжесть и
данные показываются и пропускаются. Значение найденного ключа не печатается никогда — только
файл и строка. Обход есть и он громкий: `--force`.

**Что делает найденный секрет — решает видимость, а не сама находка.** Публичный репозиторий:
стоп, без варианта «приму риск» — принимать его пришлось бы не одному человеку. Приватный:
находки названы поимённо и принимаются отдельным «да», работа не встаёт. Неизвестная видимость:
стоп, но с выходом (`--private` или вопрос в терминале). Приватность берётся сначала из
проверяемого (создаём сами — знаем; GitHub спрашивается через `gh`) и только потом со слов
человека; слово хоста бьёт утверждение.

Настройкой это не стало намеренно: ключ вида `publish_secrets = off` выключил бы предупреждение
навсегда и молча, а по [D3](../PRINCIPLES.md#d3-обход-не-обязан-быть-невозможным--обязан-быть-видимым)
обход обязан быть видимым. Ратификация видна каждый раз и стоит одного нажатия.

Глагол ничего не коммитит: он отправляет то, что уже сохранено. Это то же правило [B6](../PRINCIPLES.md#b6-глагол-трогает-только-то-что-сам-изменил),
из-за которого у `fraim commit` нет режима «всё».

**Правда о копии — с хоста, а не из своих записей.** `refs/remotes` это память ЭТОЙ машины о
прошлых отправках, и врёт она ровно там, где ошибка дороже всего: репозиторий создан и пуст,
ветку на хосте снесли, историю положили туда из другого места. Поэтому `publish` спрашивает
хост (`ls-remote`) и печатает состояние строкой в плане: пусто · старее · то же самое · там
есть работа, которой здесь нет. Сторож ту же дыру видит **без сети** и с другой стороны: адрес
прописан, а remote-tracking веток нет ни одной — значит настройку начали и не довели. Это
отдельная находка, а не «N точек не уехали»: величина другая ([D5](../PRINCIPLES.md#d5-детектор-меряет-то-на-что-показывает--и-не-считает-собственную-бухгалтерию)),
и порог к ней не применяется.

**Два отказа печатают задание, а не совет.** Секрет, уже лежащий в истории, и расхождение с
хостом — обе задачи требуют суждения и инструмента, которого у системы нет: чистка истории это
её **переписывание**, а его `fraim` не делает нигде. Поэтому отказ выдаёт самодостаточный блок
для агента — путь проекта, найденное поимённо, порядок работы и границы («ничего не пушить»,
«`--force` не предлагать», «не запускать без моего „да“»). По [P0](../PRINCIPLES.md#p0-продукт-для-того-кто-не-профессиональный-разработчик)
это обязательство, а не удобство: «убери файл из истории» — это просьба об экспертизе, которой
у пользователя может не быть.

### Git — часть скелета, а не требование к пользователю

Каждая точка сохранения здесь — коммит, поэтому `fraim scaffold` **заводит репозиторий**, если
его нет: в чужом (когда репозиторий выше по дереву) не заводит никогда. Если у git не настроены
подписи, ставит локальные для этого проекта и говорит, как их сменить. Сторож замечает проект без
репозитория и несохранённые изменения фундамента.

Возврат — `fraim undo`: без аргумента показывает точки, поставленные системой, с хешем — отменяет
одну **встречным коммитом**. История не переписывается: это безопасно в общем репозитории и с
ремоутом, и саму отмену тоже можно отменить. Чужой коммит не отменяется никогда.
Ни одна процедура не просит человека выполнить git-команду.

### Настройки

Два уровня: `~/.fraim/config` (машина) и `ai/fraim.conf` (проект, едет в git).
Проект перебивает машину, машина перебивает умолчание. `fraim config` показывает не файл,
а **что действует и откуда** — именно это делает настройки понятными тому, кто их не писал.

## Что куда ставится

между ними сводится к целевому каталогу и к файлу глобальных правил.

**Одна копия в общем каталоге.** `~/.agents/skills` — пользовательский каталог открытого
стандарта, и большинство харнесов читают его рядом со своим. Вторую копию того же скилла
часть из них не прощает: Gemini CLI показывает конфликт на экране, pi, omp и Hermes пишут

`~/.agents/AGENTS.md` так же общий: его читают Cline, Warp, Goose и Kimi Code, поэтому
блок там один на всех. Где харнес читает **каталог** правил, а не один файл (Kiro, Augment,
Continue), мы кладём туда свой файл `fraim.md`, а не блок в чужой.

Двойное чтение остаётся там, где харнес читает ещё и чужой собственный каталог:
`~/.claude/skills` читают Kilo, Cursor, Crush, Goose, Grok, Warp, Augment, OpenCode и Copilot
в VS Code, а `~/.claude/CLAUDE.md` — Devin, Kilo и Grok. Текст одинаковый, так что любая
копия верна.

У Antigravity клетки нетипичные, и обе намеренные: бинарник называется `agy`, а не
`antigravity`; скиллы — в два каталога, потому что IDE читает `~/.gemini/config/skills/`, а
CLI — `~/.gemini/antigravity-cli/skills/` (так же ставит и гугловский `agents-cli`); блок —
в `~/.gemini/AGENTS.md`, а не в соседний `GEMINI.md`: тот принадлежит Gemini CLI, и его
строка пишет туда сама. Каталог `~/.gemini` общий у двух продуктов, поэтому Antigravity
опознаётся по `~/.gemini/config`, а Gemini CLI — по бинарнику `gemini` или по
`~/.gemini/settings.json`, который пишет только он.

У Hermes нет глобального `AGENTS.md`: всегда грузится только `~/.hermes/SOUL.md` — его
«личность», которую он заводит сам, и туда мы не пишем. У OpenClaw всегда грузится
`AGENTS.md` его рабочего пространства, которое заводит его онбординг по шаблону, — туда
тоже не пишем. Обоим остаются скиллы, мастер-скилл `fraim` срабатывает по описанию.

Прежние версии клали файлы туда, где харнес их не читает: `~/.pi/`, `~/.omp/` (pi и omp
живут на уровень глубже, в `…/agent/`; на живой машине pi действительно не нашёл
`/skill:orient`), `~/.devin/` (Devin CLI живёт в `~/.config/devin/`; наши скиллы он видел
только через копию Claude Code в `~/.claude/skills`, которую читает по умолчанию),
`~/.hermes/AGENTS.md`, а ещё `~/.codex/skills/` (у Codex он устарел) и
`~/.config/opencode/skills/`. `fraim init` забирает оттуда **только своё** — скиллы с
`source: fraim` и блок между нашими маркерами; чужие скиллы и текст человека остаются.

**Проверено вживую** (31.10.2026): 19 харнесов поставлены из npm/PyPI в чистый `HOME`, там
запущен `fraim init`, и сам агент показал, что видит скилл `orient` и наш блок — своей
командой (`skills list`, `debug skill`, `config`) или в системном промпте, который он отправил
на подставной локальный сервер моделей. Так проверены Claude Code, Codex, pi, omp, OpenCode,
Kilo Code, Gemini CLI, Qwen Code, Kimi Code, Mistral Vibe, Hermes, OpenClaw, Copilot CLI,
Cline, Crush, Augment, Continue, Junie и Factory Droid. Не проверить из облачной среды (закрытые
сайты загрузки): Cursor, Zed, Warp, Kiro, Devin, Antigravity, ZCode, Goose, Grok Build.

Сознательно не поддержаны: Roo Code (закрыт 15 мая 2026, репозиторий в архиве),
Windsurf (Cascade стал Devin Desktop, который делит `~/.config/devin` со строкой Devin),
Amp и Trae (пути не удалось подтвердить первоисточником).

Харнес считается установленным, если один из его бинарников есть в `PATH` **или**
существует его домашний каталог. Оба признака нужны: харнес бывает поставлен, но ещё не в
`PATH` этой сессии, и бывает в `PATH` до первого запуска. Домашний каталог — родитель
каталога скиллов; строка называет свои пути явно, когда родитель общий (`~/.agents`,
`~/.gemini`).

Ставятся только свои скиллы: каждый помечен `source: fraim` во фронтматтере, поэтому
`init` подчищает устаревшие наши и **не трогает** чужие рядом.

Плюс к этому Claude Code можно поставить как плагин — тогда приезжает готовый канал
обновлений:

```
/plugin marketplace add modehustle/aiframework
/plugin install fraim
```

### Почему POSIX shell

Открытый вопрос из `PRODUCT.md` закрыт в пользу shell, потому что нулевые зависимости
здесь не удобство, а требование: сторож обязан запускаться в контейнере, в GitHub
Actions и на голом сервере, где рантайма может не быть вовсе. Node или Python сделали
бы `npm i -g` естественнее, но потребовали бы рантайм ровно там, где сторожу он не
нужен. А поверхность CLI мала и по природе своей файловая — копирование каталогов,
`git log`, mtime, — то есть ровно то, для чего shell и сделан. npm-обёртку, если она
понадобится, всегда можно добавить сверху.

### Почему процедура — один файл

Правило «скилл = ровно один `SKILL.md`» — не аккуратность, а ограничение совместимости.
Hermes при установке с URL забирает только `SKILL.md` и теряет `references/` и
`scripts/` рядом; omp обнаруживает скиллы на один уровень вниз, нерекурсивно. Процедура,
растащенная по вспомогательным файлам, приехала бы к обоим сломанной. Тест
`в каждом скилле ровно один файл` стоит на страже этого.

### Скелет — код, содержимое — текст

Форма проекта (какие файлы, какие папки, какие заголовки) фиксирована, поэтому это код:
`fraim scaffold` разворачивает её из шаблонов в `templates/foundation/`. Наполнение пишут
`/bootstrap` и `/onboard`. Раньше раскладку воспроизводила модель по прозе, и два проекта,
заведённые с интервалом в месяц, могли разойтись в собственных названиях разделов.

Каждый развёрнутый файл несёт маркер `fraim:stub`, и сторож различает три состояния вместо
двух: файла нет · скелет развёрнут, но не заполнен · фундамент заполнен. Без этого пустой
скелет рапортовал бы о здоровье — что хуже, чем отсутствие файлов вовсе.

### Источник правды — фронтматтер

Имя, описание и тир модели каждой процедуры живут во фронтматтере самого файла
процедуры. Список процедур нигде не захардкожен: всё, что их перечисляет, идёт через
`fraim_procedures`, который читает каталог. `procedures/manifest.json` **генерируется**
из фронтматтера (`fraim build`) и существует как объявленный артефакт обмена для
будущих не-shell генераторов и для CI — но ничего в этом репозитории его не читает,
чтобы источник правды не раздвоился.

Следствие для описаний: они попадают во фронтматтер скилла, а **описание решает,
сработает ли автотриггер**. Ограничения стандарта Agent Skills: имя строго kebab-case
(`^[a-z0-9-]+$` — поэтому `/make-task`, а не `/make_task`), описание — до 1024 символов
и без угловых скобок.

## Обновление

Две половины, и раньше их надо было помнить обеими: привезти исходники
(`install.sh`) и разложить их по харнесам (`fraim init`). Пропустив вторую, человек
получал худшее из состояний — `fraim version` показывает новое, агент читает старое.
`fraim update` делает обе; `fraim init` остаётся отдельно, потому что нужен и без сети
(поставил новый харнес — разложи по нему то, что уже есть).

Своей реализации «привезти» в `update.sh` нет: это делает `install.sh`, и он остаётся
единственной ([B2](../PRINCIPLES.md#b2-у-детерминированного-действия-ровно-одна-реализация)).
`update_apply` его запускает, а потом делает `exec` на новый бинарник: продолжать в том же
процессе нельзя — он прочитал `lib/` до обновления.

Обнаружение отделено от действия намеренно
([D4](../PRINCIPLES.md#d4-планируем-обнаружение-а-не-действие)):

| | кто ходит в сеть | что читает |
|---|---|---|
| `fraim update`, `fraim update --check`, `fraim doctor`, `fraim init` | да, не чаще `update_check_days` | пишут кэш `~/.fraim/update-check` |
| `fraim status`, меню, сторож | **никогда** | только кэш |

Сторож обязан быть оффлайновым и мгновенным (`SCHEDULING.md`, слой 1), поэтому находка
`system-update` читает файл. Кэш хранит и «хост не ответил» отдельным состоянием: молчание
сети не должно выглядеть как здоровье
([D1](../PRINCIPLES.md#d1-отсутствие-данных-не-должно-выглядеть-как-данные)).

Демона система не заводит. Настоящее автообновление — строка `fraim update` в том
планировщике, который у пользователя уже есть; среда принадлежит ему
([C1](../PRINCIPLES.md#c1-среда--это-выбор-пользователя-а-не-инвариант-системы)).
