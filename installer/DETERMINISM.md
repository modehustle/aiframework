# Детерминированный слой: глаголы и гейты

> Ответ на вопрос «как сделать хуки, которые работают в любом агенте». Короткий ответ:
> в большинстве случаев хуки не нужны — нужны глаголы. А там, где нужен именно контроль,
> работает не событие, а **гейт**.

## Проблема

В системе есть действия, которые **всегда одинаковые**: сделать коммит, дописать строку в
журнал хотфиксов в точном формате, создать папку задачи, перенести её в архив с меткой
времени, поставить маркер прунинга.

До этого слоя все они были описаны **прозой внутри процедуры** и исполнялись моделью на её
усмотрение. То есть детерминированную работу мы поручали недетерминированному исполнителю.

Это не гипотетический риск. Формат штампа provenance читает детектор протухших планов: модель,
которая написала её чуть иначе, **молча ломает счётчик**, и никто не узнает, пока фундамент
не сгниёт. Штамп `System: fraim <версия>` в плане нужен, чтобы поймать план, написанный старой
версией системы, — но если модель его забыла, ловить нечего.

## Арифметика, из-за которой это не мелочь

Пусть модель выполняет каждый механический шаг правильно в 95% случаев — это оптимистично.
Шесть таких шагов в одной процедуре дают `0.95⁶ ≈ 74%`. То есть примерно **каждая четвёртая
задача** закрывается с тихим дефектом в служебном слое.

Умножь на месяцы работы — вот откуда берётся дрейф, против которого построена вся система.
Причём это самый обидный его сорт: не ошибка суждения, а несделанная механика.

## Два класса действий

Ключ к решению — заметить, что «детерминированные действия» бывают двух разных видов, и
универсальный механизм нужен только одному.

| | Класс 1 | Класс 2 |
|---|---|---|
| Что это | часть хода самой процедуры: коммит, запись в журнал, создание папки, архивация | должно сработать независимо от того, сотрудничает модель или нет: статус при входе в сессию, принуждение к инварианту 0.4 |
| Когда | пока модель работает, по порядку | вне хода процедуры |
| Чем закрывается | **глагол CLI** | хук харнеса — **или гейт** |
| Универсально? | да: shell-команда работает везде | нет: у каждого харнеса свои хуки, у части их нет вовсе |

Почти всё, что болит, — Класс 1. И ему не нужны хуки: нужно, чтобы действие стало **одной
командой**.

## Глаголы

Модель по-прежнему решает **когда** позвать глагол. Но формат, пути, метки времени и коммит
перестают быть её делом.

| Глагол | Заменил прозу в | Что делает детерминированно |
|---|---|---|
| `fraim scaffold` | bootstrap, onboard | 4 файла фундамента + `ai/` + `.gitignore` + `ai/fraim.conf` по шаблонам; никогда не перезаписывает |
| `fraim task-new СЛАГ` | make-task 1.8 | папка задачи + `## Plan provenance` с датой, git-ref и версией системы |
| `fraim task-block СЛАГ` | run-task 4d.3, reconcile A.2 | `blockers.md` по шаблону |
| `fraim task-result СЛАГ` | run-task 8.1, 9.3 | `result.md` по шаблону; `--reconcile` добавляет раздел расхождений, `--reset` снимает отчёт |
| `fraim task-revise СЛАГ ДЕФЕКТ ИСПРАВЛЕНО` | revise-task 3–5 | нумерованная запись ревизии + свежий штамп провенанса + снятый блокер + коммит |
| `fraim plan-seal СЛАГ` | make-task 3 (механическая половина) и 4.0 | **гейт** → провенанс, самодостаточность, разделы, непустая проверка, существующие пути + коммит `plan: <слаг>` |
| `fraim decide ЗАГОЛОВОК` | run-task 7.2, reconcile 2, onboard 3, bootstrap | запись в `DECISIONS.md`: место (новое сверху), заголовок с датой, `--supersedes`; **тело приходит на stdin** |
| `fraim pitfall СТРОКА…` | run-task 9.8 | строки в `## Known Pitfalls / Lessons` файла `CONVENTIONS.md` — в конец именно этого раздела |
| `fraim task-seal СЛАГ` | run-task 10 | **гейт** → архив с меткой времени + коммит `archive: <слаг>` |
| `fraim reconcile-seal СЛАГ` | reconcile-task 7 | **гейт** (те же три предусловия + расхождения) → архив + коммит |
| `fraim investigate-new СЛАГ` | investigate 2.2 | папка расследования + `findings.md` по схеме + провенанс |
| `fraim investigate-seal СЛАГ` | investigate 5 | **гейт** (ровно одна ветка исхода + отчёт об уборке) → архив + коммит |
| `fraim prune-mark` | prune 3–4 | маркер `--- pruned <дата> ---` + коммит гардинга |
| `fraim commit ВИД ТЕКСТ ПУТЬ…` | run-task 8.3–8.4 и 9.9, onboard, docker-deploy 9.5, expose 6.3 | точка сохранения ровно по перечисленным путям |
| `fraim undo [ХЕШ]` | — (не было вовсе) | показать точки системы; отменить одну встречным коммитом |
| `fraim restore ПУТЬ…` | investigate 4.2 | вернуть перечисленные пути к последней точке, созданное — удалить |
| `fraim publish` | — (была проза «попроси агента настроить») | проверка провайдера и входа, проверка того, что уедет, создание репозитория, адрес, push, сверка с хостом |

## Запись в фундамент: форма — глаголу, слова — модели

`fraim decide` — случай, где граница «форма/наполнение» проходит внутри одной команды, и это
стоит проговорить, потому что однажды этот глагол уже отвергли.

Механично здесь: место вставки (новое сверху, ничего не переписывая), заголовок с датой, пометка
`Supersedes` вместо удаления. Это описано прозой в трёх процедурах и четвёртый раз в шаблоне —
четыре описания одного формата, исполняемые моделью.

Не механично: сам текст решения. Возражение прошлой ревизии (AUDIT-VERBS 4.4) было именно про
него: тело записи многострочное — Context / Decision / Alternatives / Consequences, — и, если
передавать его аргументом командной строки, модель начнёт сокращать текст под форму. Возражение
верное, но оно било по `argv`, а не по идее глагола. Поэтому **тело приходит на stdin**:

```sh
fraim decide "storage engine" <<'EOF'
Context: …
Decision: …
Alternatives: …
Consequences: …
EOF
```

Ни `decide`, ни `pitfall` не коммитят. Точка сохранения остаётся в одном месте — `fraim commit`,
который процедура зовёт со всеми путями, которые тронула. Иначе шаг, который собирался дописать
строку, тихо порождал бы второй коммит.

Коммит везде идёт через одну функцию, поэтому формат сообщений единый: `<вид>: <текст>`.
Отключается настройкой `commit_verbs = off` — на случай проекта, где коммитами распоряжается
что-то другое.

**У `fraim commit` намеренно нет аргумента «всё».** В папке проекта лежит не только то, что
изменила система: там незаконченная работа человека, его `.env`, его данные. Глагол сохраняет
**только то, что сам изменил**, и это единственное правило, которое делает точки сохранения
безопасными в чужом репозитории — и в репозитории того, кто не умеет проверить, что попало в
индекс.

## Гейты

Гейт ценен не тем, что делает работу, а тем, что **отказывает**. Их четыре, по одному на каждый
выход наружу: из планирования, из задачи, из дрейфнувшей сессии, из расследования.

`fraim plan-seal` — дверь из **планирования**, и она появилась последней, хотя ставка на ней
самая высокая. Три остальных гейта стоят на выходах из исполнения; выход из `/make-task` был
обычным коммитом, перед которым автор плана прогонял по своей же работе двенадцать пунктов
самоконтроля. Это ровно та конструкция, которую B3 уже отвергла для инварианта 0.4: отчитывался
тот же, кого просили. А план — единственный артефакт, которому исполнитель верит вслепую: он
приезжает в чистый чат, где нет ни планировщика, ни разговора, с которым можно сверить.

Семь из двенадцати пунктов — это `grep` и `test -e`, и они переехали в гейт: маркер заготовки,
плейсхолдеры, целость штампа провенанса, фразы «как мы обсуждали» (G1), присутствие и непустота
обязательных разделов, непустая проверка, существование каждого пути из `Codebase Context` и
`Files to Change` (кроме тех, у которых `Action: create`). Оставшиеся пять — суждение
(объективно ли проверяем критерий, полон ли список зависимостей), и они остаются человеку.

`fraim task-seal` **отказывается** архивировать задачу, если:

1. нет `result.md` — задача не исполнена;
2. есть `blockers.md` — задача заблокирована, ей дорога в `/revise-task`, а не в архив;
3. в `result.md` нет раздела `## Foundation updated`, он пуст или в нём остались
   незаполненные плейсхолдеры.

Третья проверка — главная. `PRODUCT.md` признаёт прямым текстом: «на каждой задаче обновление
фундамента доверяется исполнителю **на слово**». Инвариант 0.4 был просьбой, о выполнении
которой отчитывался тот же, кого просили.

Гейт превращает просьбу в **предусловие**: единственная дверь из задачи наружу принадлежит нам.

`fraim reconcile-seal` — вторая дверь, для сессии, которая ушла в живую отладку. Те же три
проверки плюс четвёртая: непустой раздел `## Divergence from plan`. Именно ради него процедура
и существует; до этого слоя она архивировала прозой — мимо всех проверок, ровно там, где
честность записи нужнее всего.

`fraim investigate-seal` — третья. Заполнена **ровно одна** ветка исхода (ни одной — расследование
бросили, обе — его не довели) и непустой `## Restored to baseline`. Второе важнее: уборка после
расследования — единственная механика в системе, отсутствие которой не видно никому, пока
неудалённая строка в живой базе не выстрелит через месяц.

Важно, что это не запрет ничего не менять. Исполнитель имеет полное право не тронуть фундамент —
но обязан **сказать** об этом, и его слова уезжают в архив как запись. Отход есть, он просто
оставляет след. Флага `--force` нет намеренно: гейт, который обходится флагом, — не гейт.

## Почему это и есть универсальные хуки

Хук харнеса просит среду выстрелить событием. Но сред много, события у всех разные, а у
некоторых их нет.

Гейт не просит ничего. Он не нуждается в событии, потому что **выход только один и он наш**.

И работает это везде, где есть shell: в Claude Code, в Codex, в Hermes, в контейнере, в GitHub
Actions. Ровно та универсальность, которой у хуков быть не может.

Хуки харнеса при этом никуда не деваются — они ложатся **вторым поясом** там, где среда даёт:
`SessionStart` может сам прогнать `fraim status`, чтобы вердикт приезжал в контекст без единого
нажатия. Но система не зависит от их наличия.

## Честные границы

**Модель может обойти CLI и написать файлы руками.** Это правда, и делать вид, что нет,
было бы нечестно. Против этого работает три вещи:

1. процедура прямо велит звать глагол, а не воспроизводить результат;
2. `fraim status` замечает последствия — задача исполнена и не запечатана, расследование доведено
   до исхода и не заархивировано, фундамент изменён и не сохранён, репозитория нет вовсе;
3. где у харнеса есть хуки — они добавляются сверху.

Заявка не «обойти невозможно», а **«обход виден»**. Для системы, вся ценность которой в
обнаружении дрейфа, этого достаточно — это ровно тот же приём, что и везде у нас.

## Правило одной реализации

> **У детерминированного действия ровно одна реализация — в CLI. Прозаического запасного
> пути нет. Нет `fraim` — процедура останавливается и говорит об этом.**

Прецедент в системе уже был: `/docker-deploy` не делает хостовые действия сам, он тормозит и
просит человека.

Противоречия с принципом «скиллы работают без рантайма» здесь нет, потому что линия проходит
не между средами, а между чтением и изменением:

| | Нужен CLI |
|---|---|
| прочитать процедуру, написать план, рассуждать | нет — потому процедура и остаётся одним файлом |
| детерминированно изменить состояние | да, всегда |

Контейнер без `fraim` спокойно читает `/make-task` и пишет план. Разворачивать новый проект
в контейнере без установленного инструмента — сценарий, которого не существует.

## Git как данность

Отдельный случай того же правила, и стоит проговорить его целиком, потому что решался он
отдельно.

Каждая точка сохранения в системе — коммит. Значит проект без репозитория — это проект, в
котором ничего нельзя вернуть, а человек, который не знает git, репозиторий не заведёт. Поэтому
**репозиторий — часть скелета**: `fraim scaffold` создаёт его, если его нет ни здесь, ни выше по
дереву (внутри чужого checkout'а — никогда: вложенный репозиторий тихо отцепил бы файлы человека
от его же истории), и ставит локальные подписи коммитов, если у git их нет вообще.

Что система берёт от git — ровно четыре вещи: точка сохранения, возврат к ней, восстановление
рабочего дерева, видимость несохранённого. Ветки, ремоуты, ребейз, мерж, stash — не нужны ни
одной процедуре, и потому в тексте процедур не появляются. Это и есть ответ на «сделать git
данностью»: не обернуть его целиком, а пользоваться подмножеством и не произносить остальное.

Три правила, из которых следует остальное:

1. **Глагол трогает только те пути, которые сам изменил.** Ни у `commit`, ни у `restore` нет
   аргумента «всё». Отсюда: никто никогда не решает, «что не коммитить» — `.env`, данные и чужая
   незаконченная работа не попадают в индекс, потому что их туда не клали. Это одинаково верно
   и в пустой папке, и в чужом пятилетнем репозитории.
2. **Отмена — встречный коммит, а не переписанная история.** `fraim undo` делает revert:
   безопасно при общей работе и с ремоутом, и это тот же приём, что «supersede, never delete» в
   `DECISIONS.md`. Свои точки система узнаёт по трейлеру `fraim: <версия>` в теле коммита;
   чужой коммит не отменяется никогда.
3. **Ни одна процедура не просит человека выполнить git-команду.** Проверяется тестом: любое
   `git commit|add|init|restore|checkout|reset|stash|clean|push` в тексте процедур — ошибка.

Что из этого следовало, но было не так: `/investigate` требовал чистого дерева, потому что его
уборка делала `git restore .` — а это снесло бы незакоммиченную работу человека. Требование было
костылём под опасную команду, и заодно перекладывало git-задачу на того, кто её не умеет. Теперь
уборка идёт `fraim restore` по манифесту, и требование исчезло вместе с причиной.
